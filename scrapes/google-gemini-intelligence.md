## 2. Core Prompting Intelligence for Promptsmith

### A. The Directives vs. Inquiries Mandate (`gemini-cli`)
In Google Gemini's agent architecture, models operate under a strict dual-mode assumption:
- **Inquiries** (requests for analysis, advice, observations, e.g., *"Can you tell me how to..."*, *"Without changing anything..."*): The model's scope is strictly bounded to read-only research and analysis. It **must not** modify files until an explicit Directive is issued.
- **Directives** (unambiguous requests for action or implementation): The model is authorized to act autonomously and modify files.
- **Rule for Promptsmith Briefs:** Gemini models are prompted: *"Assume all requests are Inquiries unless they contain an explicit instruction to perform a task."* Coding-agent briefs generated by Promptsmith for `agy` or Gemini CLI must use imperative action verbs (`implement`, `change`, `refactor`, `fix`) and state explicit done criteria to prevent the agent from stalling in passive inquiry mode.

### B. Strategic Sub-Agent Delegation as Context Compressors (`gemini-cli`)
- **Main Context as Sacred Resource:** *"Operate as a strategic orchestrator. Your own context window is your most precious resource. Every turn you take adds to the permanent session history."*
- **Compression Mechanism:** When the parent agent delegates to a subagent, the subagent's multi-turn execution is collapsed and returned as a single summary block in the parent history, saving up to 80% of context tokens.
- **High-Impact Delegation Triggers:**
  1. Repetitive batch tasks (>3 files or repetitive steps).
  2. High-volume output commands (verbose builds, full test suites, broad file sweeps).
  3. Speculative trial-and-error investigations.
- **Concurrency Safety Mandate:** Never spawn parallel subagents that mutate the same files or shared resources. Parallel execution is strictly reserved for independent read-only sweeps.

### C. Contextual Hierarchy & Memory Precedence (`gemini-cli`)
Promptsmith's `references/repo-rules.md` can adopt Google's official 4-layer context resolution model:
1. `<project_context>` / Sub-directories: Specific local overrides.
2. Workspace Root (`GEMINI.md` / `AGENTS.md`): Repository-wide mandates. Supersedes global preferences.
3. `<extension_context>`: Supplementary knowledge and tools.
4. `<global_context>` (`~/.gemini/GEMINI.md`): Foundational personal user preferences.
- **Override Scope:** Contextual files override operational behaviors (coding style, conventions, workflow, tools), but **cannot** override core security, safety, and agent integrity rules.

### D. Narration vs. Post-Edit Silence (`gemini-cli`)
- **Explain Before Acting:** Never call tools in silence; provide a concise, single-sentence explanation of intent or strategy immediately before executing tool calls (except for repetitive low-level discovery reads).
- **Silence After Completion:** *"After completing a code modification or file operation do not provide summaries unless asked."* This directly supports Promptsmith's ultra-terse delivery principle.

### E. Modern Gemini 3.x Model Matrix & Interactions API (`gemini-skills`)
- **Active Models:**
  - `gemini-3.8-flash`: 1M tokens context, 65k output. Default for high-speed agentic, multimodal, and coding tasks.
  - `gemini-3.5-flash-lite`: 1M tokens. Lowest-cost 3.5 model for high-frequency execution.
  - `gemini-3.1-pro-preview`: 1M tokens. Complex architectural reasoning, deep research, coding audits.
  - `gemini-3.1-flash-lite`: Ultra-fast lightweight tasks.
- **Deprecated / Cruft Models:** `gemini-2.5-*`, `gemini-2.0-*`, `gemini-1.5-*`. Any prompt or harness config mentioning these is outdated.
- **Interactions API Architecture:** Multi-turn chaining using `previous_interaction_id` (server-side context management) rather than serializing chat history client-side.

### F. Prompt Engineering Paradigms (`cookbook`)
- **Prefix Structuring:** Clear structural tag anchors (`<instructions>`, `<context>`, `<input>`, `<output_format>`).
- **Class-Balanced Exemplars:** Providing 3–5 diverse input-output examples with balanced classification labels and edge cases to avoid single-exemplar overfitting.
- **Prompt Chaining over Monolithic Prompts:** Decomposing complex multi-stage tasks into sequential prompt steps (research -> strategy -> execution -> verification) rather than a single monolithic prompt.
